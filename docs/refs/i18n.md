# i18n Reference

## Open This When

- You add or change translation keys.
- You update namespace routing or message loading.
- You need to debug extractor behavior.

## Read First

- `apps/webapp/src/tolgee/shared.ts`: namespace model and route-based namespace loading.
- `apps/webapp/src/tolgee/server.tsx`: server translation entrypoints.
- `apps/webapp/src/tolgee/client.tsx`: client provider and namespace hydration.
- `apps/webapp/tolgee.config.cjs`: Tolgee CLI config.
- `apps/webapp/tolgee-extractor.mjs`: custom key extraction and namespace inference.
- `apps/webapp/messages/`: namespace-based locale catalogs.

## Key Rules

1. Keep keys stable and statically extractable.
2. Use namespace-prefixed keys when needed.
3. Provide a static English default for every key. `tolgee sync` creates a key without one
   empty, and the next pull omits it from every catalog, so all locales show the code
   fallback. `src/tolgee/extracted-key-defaults.test.ts` fails on such keys.
4. Keep extractor namespace mapping aligned with `messages/<namespace>/<locale>.json`.

## Static Defaults

The extractor reads a default from:

- The second `t()` argument: a string literal, or an identifier bound once in the same file to a
  string literal (`const FALLBACK = "..."`).
- A sibling of a `fooKey` property in the same object, in this order: `fooDefault`,
  `fooFallback`, `fallbackFoo`, `defaultFoo`, then `foo` itself
  (`{ title: "Time", titleKey: "settings.x.title" }`). When `fooKey` is the object's only
  `*Key` property, a `fallback`, `defaultValue` or `default` sibling also counts.
- `{ key, fallback }` objects, `[key, fallback]` tuples, and JSX `*Key="..."` props with a
  `fallback` attribute.

It cannot read computed defaults: ternaries, template literals, function calls,
`["a", "b"].join(" ")` or member access such as `COPY.title`. Use one static `t()` call per key
(choose between calls, not between keys inside one call). Write plurals as ICU
(`{count, plural, one {# request} other {# requests}}`) instead of choosing between two strings.

## Workflow

1. Add or update keys in code.
2. Ensure namespace mapping is correct.
3. Sync/update message files through the existing Tolgee workflow.

From `apps/webapp`, use `tolgee sync --remove-unused` followed by `pnpm i18n:pull`.
The pull command also regenerates the source membership and collision metadata
used by selective catalog loading. Tests, builds, and development startup regenerate
that metadata as well, so a direct `tolgee pull` cannot leave it stale.

`sync` creates missing keys and seeds their base-language defaults; it does not
update translations on existing keys. Correct empty translations, outdated copy,
and malformed placeholders in Tolgee (or through a targeted CLI import), then pull
again. Runtime interpolation uses ICU `{name}` placeholders; `${expression}` source
text must never be stored as translated copy. Do not repair generated locale files
by hand.
