## Build completion cancellation

The retained successful head build contains exactly 76 generic completion
rejections, all for `connection()`: 38 logged as “Failed to load your documents”
and 38 as “Failed to load your requested documents”. They point to the localized
My Documents render, rather than 76 distinct application route families.

Installed Next 16.4.0's `dynamic-rendering-utils.js` identifies this exact message
as `HANGING_PROMISE_REJECTION`; `connection.js` deliberately returns that hanging
promise in prerender phases and resolves in a real production request. The
existing personnel-file actions' broad catch/failure adapters log these
rejections while My Documents starts the reads concurrently. This establishes
the logging path and framework cancellation class. It does not establish a
real-request failure, unauthorized result, broken dynamic boundary or leaked
tenant data. The latest original build's zero matching messages remains a real
comparison difference, not a clean-runtime claim for head.
