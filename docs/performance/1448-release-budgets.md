## Two resource windows

C1 records completed transfers through usable/clock readiness. A finite number in that ledger is an observed-window lower bound, not full initial cost. Pending Script/RSC requests censor the corresponding byte cohort. An incomplete resource window censors total/inline comparisons. The comparison report retains the original pending counts, failed requests, incomplete windows, failure details and null percentiles. It cannot fulfill full-resource acceptance without a complete matched companion.

`settled-resources.mjs` runs a separate authenticated pass after the corrected primary pass. It follows the original first-document and repeat-Link recipes with **twenty new browser contexts for each required cohort/mode** and preserves ordinary runtime cache warming. It does not rerun functional mutations; the original five functional visits remain timing/behavior checks. Repeating Last Year then Custom Range includes prior annual work. `prepare(false)` can leave priming reads in flight. Neither pass measures an isolated month computation or guarantees a warm data cache.

The companion keeps `atReady` and `settled` as separate page-CDP diagnostics with their existing partial flags. New `wireAtReady` and `wireSettled` snapshots drive full resource acceptance. The companion records a readiness snapshot, then waits for **1,000 ms with no mandatory finite network activity**, with a **10,000 ms post-readiness cap** and 50 ms observation polls. It drains Document, Script, route RSC and other finite requests, including requests starting after readiness. Unknown finite Fetch/XHR work remains mandatory. Response MIME identifies RSC when request headers do not. Redirect hop lengths are retained; unknown lengths, HTTP/network errors, pending mandatory requests and caps remain censored. The cap does not extend primary C1 timing.

Requests explicitly marked `Next-Router-Prefetch: 1`, `Purpose: prefetch` or `Sec-Purpose: prefetch` are counted separately from mandatory route work. Their bytes/pending/errors remain in the artifact; intentional partial prefetch cannot hold settling forever. WebSocket/EventSource traffic is separately counted, including CDP WebSocket lifecycle events. Other finite background polling is not silently excluded and can exhaust the cap. Mandatory inherited priming requests are counted and drained separately; their completed bytes are reported but not charged to the measured navigation. Completed priming requests are excluded when the measured navigation begins.

In the companion, mandatory request traces retain the measured trace ID; explicitly marked prefetch and identifiable long-lived requests use a separate recorded background trace ID and priming uses a prerequisite trace ID. The backend finalizer requires exact native observer/PG/rows/cache/event-loop coverage and zero rejected batches for each mandatory trace. Raw prefetch/priming/background counts remain available; they are not claimed as zero cost. The companion measures a bounded finite-resource window, not all future page-lifetime work. No global cache clearing, byte-blocking interception, changed route workload or full-browser `networkidle` claim is used.

Wire totals reconcile against the sum of per-trace MIME groups, including explicit background and inherited work. Unknown finite responses remain mandatory; pending requests, errors, observation overflows and ambiguous inherited redirect boundaries remain censored. Completed byte totals exclude inherited bytes, while inherited completions are recorded and drained separately. The whole-run native proof still sums all three identities, so moving explicit prefetch to the registered background trace cannot discard native SQL. Wire-body bytes exclude HTTP headers and transport framing. They are never added to CDP encoded lengths or decoded inline Flight.

The primary runner retains its required legacy `javascriptP95Bytes` field in **CDP units**, derived as the fixed byte allowance over the condition maximum observed through readiness. `primaryResourceBudgetProvenance` labels it diagnostic-only and a lower bound, never a full-cost before percentile. It is not overwritten with a proxy-body ceiling. With matched complete wire evidence, primary byte comparisons remain `passed: null` and retain the unavailable-before reason; any legacy main-finalizer JavaScript overage stays in `retainedPrimaryGates`. Only the separately matched wire body gate determines full resource acceptance. A main-finalizer overage cannot turn an unknown-before CDP comparison into a false full-resource failure, and the original pending flags are never relabeled passed.
