# Responsive sidebar preparation qualification

An unchanged desktop Dashboard reproduction exposed a stale decision in the fixture's global navigation preparation. The sidebar was expanded while its navigation was still loading. The intended link then became visible and received the pointer, but preparation clicked the trigger anyway. That closed the sidebar and moved the link offscreen. The pointer guard correctly refused to click it. The [versioned evidence](evidence/1450-sidebar-reveal-v1.json) binds the six-visit reproduction and its complete native closure. The historical interrupted C9 failure had no pointer witness, so its cause remains unknown and that capture remains invalid.

Global sidebar reveal now waits for a known responsive state. An expanded desktop sidebar or open mobile sheet waits for the requested link. A known closed sidebar receives one trusted opening click, followed by verification that it is open and the requested link is available. A CSS-hidden server desktop branch is not treated as mobile readiness. Unknown states fail within the original absolute deadline; no input or navigation is retried.

Five actual Chrome/HTTP counterfactual journeys established the old desktop failure, the candidate's intended navigation, mobile closed/open behavior, and rejection of unknown state. A private compiled candidate then passed 27 visits: desktop Dashboard first-document plus twenty Links, followed by mobile Dashboard, time tracking and reports first-document plus one Link each. All ordinary UI, native, transport and measured five-metric requirements passed, with no pending traces or witness overflow. These bounded mobile checks are not twenty-sample cohorts.

The private candidate used an exact normal-measure copy with only its journey import substituted; the full C9 plan and every other copied module stayed unchanged. Its two helper functions match the shipped functions' syntax trees after ignoring formatting and equivalent split constant declarations. Public `performSteps` tests were red before the change and green afterward; all 32 focused tests pass. Every other top-level journey statement, including the pointer guard, Period keyboard operation and calendar steps, is unchanged. The only existing statement changed is the controlled global-sidebar reveal branch; other reveal triggers retain their behavior.

The application, Next patch, dependencies, generated recipes, dates, sample counts, factors and deadlines are unchanged. The accepted runtime evidence belongs to the private candidate, not a new normal-source capture. Full C10 acceptance still requires its prospective source binding and complete controlled captures. Prior failed attempts remain preserved.
