# GET legacy clock source qualification

Original 2ef has an additive ten-file UI variant. It changes only the approved use-time-clock hook pin and preserves the earlier ten-file closure for old sources. The new variant requires a separately hashed common certificate for the exact Original 2ef and HEAD 405 sources, their actual build manifest joins, and four transport files: route, DTO, HTTP client and unchanged task-state model. Those four files are acquired and checked separately; ten UI rows are not a claim of a complete GET transport closure.

The certificate must retain the approved four production hunks and both phase source records. Its physical bytes, selected Original files, canonical hashes and Git blobs are joined during bounded file acquisition. The new compiled Original cannot omit the certificate or fall back to old hook pins. Only baseline phase is supported. HEAD 405 continues to supply no legacy readiness authority and is explicitly unsupported by this qualifier. No browser readiness, deadline, request or write behavior changes.

This code change alone does not qualify either new build. Root must complete and review fresh CI/build/common/source records before issuing the new configuration; all old qualified artifacts and failed observations remain unchanged.
