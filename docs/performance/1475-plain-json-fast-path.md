# Completed Plain-JSON semantic coverage

The parser can omit semantic descendants of an already completed, false-force
Plain certificate. This is a source-pinned algorithm change, not a cancellation
exemption. It creates no missing-body or unresolved-reference permission.

Eligibility is unchanged from the stronger shadow summary: the same body-local
parser object, ordinary/null-tag/nonstream provenance, role exactly required or
component-data, supported own flag presence/value and bounded known ancestry.
Every Plain child was already validated during the existing charged eager walk.
No new traversal, resolution, role memo or promotion of depth-only entries occurs.
Dollar-prefixed strings, removed/proto fields, nonfinite/undefined values, exotic
containers, opaque/binary data, skipped elements and borrowed readiness stay out.

The existing local-inspected guard and charged shared-model guard run first,
in their original order, followed by the real root width guard. For a completed
summary N/W and real outside queue Q, omission requires BOTH Q+W<=100000 and
inspected+N-1<=100000. A miss or bound exclusion uses the original expansion.
An applied hit adds N-1 to logical inspected coverage, leaves the outside queue
unchanged and takes the existing continue/finally path. N1 omits nothing and
continues through the original expansion. All caps remain unchanged.

N/W follow actual Object.keys order and reverse LIFO processing:
N=1+sum(child.N), W=max(childCount,max_j(j+child.W)). Thus descendant width,
not just root width, and every omitted monotonic logical inspection are proved.
The global framed E scan, action success:false/error and all independent typed
transport/tree/data/Map/boundary postchecks still run. Plain has zero protocol
counter effect; main/partial output and required/error claims do not change.

Actual modelSteps/chargedWork, pops, scheduled children and diagnostic census
allocation record actual work. They intentionally decrease when descendants are
omitted. They are never filled with simulated pops or charges. The shared100000
model limit remains a cap on actual parser work, including eager/outlined and
embedded work. Each inspection separately preserves logical100000 coverage.

The new plainJsonFastPath observation reports applied hits by the two roles,
certificate-covered descendants, maxima, bound exclusions, logicalInspected and
noPopGuardAttempts. At every semantic snapshot:

    logicalInspected = actual observations + covered descendants + no-pop attempts

A local-inspected no-pop failure charges zero; a shared-model no-pop failure
charges one. The existing work accounting remains pre+pop+guard+post, with active
prefix projection before finally and one eventual commit. Early pre-queue cost
snapshots report zero logical coverage without accessing a later lexical binding.

plainJsonShadow.skippingEnabled is now true. Shadow counts mean opportunities
actually examined by the optimized walk. Historical shadow hit/node totals were
overlapping availability observations; they are not measured saved work. New
covered-descendant counts describe logical proof coverage, not timing savings or
a prediction that a formerly capped payload will now complete.

Prospective qualification uses only synthetic public-parser tests and a fresh
Root-operated normal capture. Historical failed captures retain their original
UNKNOWN verdicts. No captured payload is reparsed or retroactively admitted.
