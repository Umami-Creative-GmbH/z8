# Passive clock status GET observer

This prospective observer supports the proposed same-origin GET /api/time-clock/status without initiating a request. It is an observer candidate only; the application change and new baseline builds require separate approval and qualification.

The existing request/response listeners accept only the exact canonical URL, GET method, empty redirect chain, HTTP 200 and application/json MIME. Query strings, fragments, credentials, foreign origins and redirected responses are excluded. Ineligible HTTP responses are recorded without reading a body. Eligible JSON must satisfy the proposed strict four-field root, five-field work period and four-field task schema, canonical UTC instants and employee/clock/period consistency. Text above 4 MiB is rejected before JSON parsing. That post-read check is not a claim about preallocation or the browser transport's memory ownership.

Only hasEmployee and isClockedIn feed the existing knownStatus cache. The existing DOM/status readiness predicate, qualified legacy branch, write result, deadlines and calls remain unchanged. GET records use source page-response-clock-status-get and a null action digest; old Next-action processing remains supported. Both sources share the existing 32 rows, 32 KiB total and 960-byte per-row reservation, made before metadata is retained. Bodies, DTO identifiers, task names, dates, URLs and error messages are never added to snapshots. A missing GET request row cannot acquire status authority.

The public test seam is openPublicHeaderClock with a mocked Page and its existing event callbacks. Tests cover the previously ignored valid GET, DTO and selector negatives, body failure, unchanged DOM pairing, privacy, shared retention and absence of extra Page calls. They do not prove a real deployed route, new build or runtime behavior.

Fresh-build qualification remains separate. Preserve the currently qualified Original c6ee and HEAD 5ac builds and every failed capture. After user approval, qualify exact identical GET production hunks on both sources, run fresh CI builds and collect their manifests/registries, common source certificate, startup/actor facts and public-source proofs. The old integration producer V5, v32 metadata preparer, legacy clock ten-file qualification, Original source profile and C13 guard G5 pin the old sources or source bytes and must not be relabeled. New exact reviewed successors must freeze before final functional D; actual pins come only from completed builds. HEAD never borrows Original temporary-value authority. No numerical or functional acceptance is supplied by this observer.
