# Pointer navigation qualification

C6 stopped after 170 samples with one directory Link timeout. The failed visit reached the finance route, but its actual pointer target was not recorded. Its cause remains unknown. The subsequent 21-visit diagnostic completed every journey and all native closures; its overall witness remained censored because the CDP request witness overflowed. Neither run establishes a repair.

The [versioned counterfactual](evidence/1450-pointer-counterfactual-v1.json) records seven actual Chrome journeys against an isolated synthetic HTTP server. The old helper timed out on the first clipped duplicate, and dispatched a wrong trusted click in the hover-shift and delayed-grid cases. A private candidate reached the intended link in all three cases. These are module counterexamples, not retrospective proof of C6's pointer path.

The shipped helper scrolls an offscreen eligible target, checks the actual clickable point, hovers, and checks that point again before one trusted click. Only the two known node-unavailable errors can retry selection before dispatch. Arbitrary protocol errors and dispatched-click failures propagate. Selection and the locator share the original absolute deadline.

The actual Link, route, sample counts, numeric factors and timeouts stay unchanged on both before and HEAD. Application and dependency inputs are unchanged.
