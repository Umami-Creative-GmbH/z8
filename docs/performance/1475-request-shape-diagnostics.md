# Observe an action request shape without admitting its temporary references

This optional diagnostic records technical request facts for `getTeamPerformanceData`. It does not reconstruct a temporary-reference map, substitute `$T`, qualify a cancellation or make an unsupported required payload clean. Existing `$T` verdicts remain UNKNOWN. Prior failed captures remain failed.

Configure `runtime.browserControl.requestShapeDiagnostic` through the existing externally SHA-pinned browser-control metadata. Its exact fields are `protocol:"request-shape-diagnostic-v1"`, `actionName:"getTeamPerformanceData"`, `compiledBuild`, `compiledManifestSha256`, `actionRegistrySha256` and `actionHeaderSha256`. Before browser/app IO, `readBrowserControlBinding` checks the compiled manifest and reads the adjacent `server/server-reference-manifest.json` with a bounded, unchanged-file check. Exactly one hashed action ID must resolve to that export in `analytics/actions.ts`. The verified selection is held privately against the actual binding object; copying or changing the binding cannot supply it. This verifies diagnostic selection, not caller lifetime or value authority.

Only a selected owned-origin POST installs request-body listeners. They observe actual chunks and actual incoming-request `end` while the original `request.pipe(upstream)` remains intact. No request is replayed, awaited, held or rewritten. Callback exceptions remain sticky observer errors. Response EOF cannot set request EOF; missing, aborted, late and pending request facts stay explicit.

The diagnostic has a deliberately smaller 16 KiB encoded input bound, depth two, 32 punctuation tokens and the existing 10,000 byte-event ceiling. These do not raise the existing 4 MiB encoded, 8 MiB decoded or 32 MiB retained limits. A fixed input buffer is reserved before allocation from the **same existing proxy response-body pool**. Metadata reserves 2 KiB per selected row. Before decoding/parsing, another 256 KiB is reserved for text, parsed strings, the bounded graph and summary. There is no second request-body pool or per-chunk list. Failed metadata reservation records an unretained selection and unknown pending count rather than inventing zero. Unsupported or oversized requests do not become known shapes.

At real EOF, bounded UTF-8/JSON inspection emits only body length/SHA, encoding enums, root/argument kinds and fixed DateRange field presence/type/canonical-Date booleans. Unknown keys are counted, never retained. Dates, timezone values, raw keys, action IDs and body text remain in RAM and are discarded. Duplicate-key absence is deliberately unproved: `duplicateKeyStatus:"not-inspected"`, `shape.known:false` and `acceptanceClaim:"none"` remain explicit. No Date is interpreted as a business day or timezone boundary. This does not prove the client's response-time temporary-map value or its lifetime.

Absent configuration installs no body tap and adds no diagnostic snapshot field. Current resource, semantic, error, native, workload, deadline and numerical gates are unchanged. No new module or protocol-list entry is needed; the two modified modules already belong to every relevant source closure.

Malformed registry JSON throws a fixed error without its original message or cause. A rejected duplicate selected request increments diagnostic ambiguity/unretained counts and makes the pending count unknown. The existing duplicate-ID guard still preserves the first row and its reservations; later callbacks and closure cannot erase that ambiguity.

Pure checks use `browser-control-collector.test.mjs` and the two mock cases selected by `--test-name-pattern='request-shape tap (observes|contains)'` in `trace-transport.test.mjs`. Root alone runs the new `request-shape tap real loopback forwarding stays byte header and status equivalent` socket test. Agents have not run that HTTP test or any app/browser/DB workload.
