# Prospective browser failure evidence

Clean-evidence policy3 retains the raw browser `failedRequests` metric in both phases. Acceptance requires a complete request-ID partition into genuine failures, unknown failures and positively proved protocol controls. Genuine or unknown measured failures block capture and budget derivation. A canceled request is never recorded as a successful application payload.

Control policy2 requires actual browser-received Flight bytes, supported framing and required model dependencies, and the same decoded body hash from a unique naturally completed proxy response. HTTP errors, Flight error rows, explicit root action failures, incomplete bodies, ambiguous identity, pending observations and caps reject the proof. Earlier policy1 Native prototypes remain unqualified; historical receipts cannot acquire policy2 controls.

The first Native family is limited to known request ExtraInfo and an exact-byte cached ancestor. It requires one prior completed same-loader cached Fetch with the same initial request identity, its exact origin response ID, and the canceled native request's exact current proxy ID. Both upstream responses must end naturally with the same typed segment/head body, length and hash as the completed cached browser response. All observed semantic Vary fields, Cookie and Authorization are compared; only Chrome's source-qualified default Accept insertion is derived. NoExtra, missing/duplicate correspondence, incomplete current responses and byte mismatches stay UNKNOWN. Raw browser failures and all resource costs remain unchanged.

That family also requires the independently qualified compiled public-source set, actual launch/profile/source observations, owned context/worker/controller facts, a single owned HttpOnly principal at both boundaries, and the complete transport-lifetime zero-Set-Cookie header census. Receipts retain these CORE inputs once per classified scope, reference them by hash, and recompute the proof on loading. Capture/finalizers additionally compare against the expected runtime and frozen operator protocol map; copying a receipt's own expected values is insufficient. Current-window membership is unchanged. Genuine protocol errors, required semantic UNKNOWNs and every existing native/error gate remain blocking. No semantic abort acknowledgement or projection exemption is implemented by this family.

Cached text readback in this first family additionally needs actual UTF-16 code-unit count, independent finished CDP dataLength sum and converted byte length all equal to the origin length, with known text/x-component and absent charset. The body hash must already match the raw origin exactly. There is no byte reconstruction, charset normalization, body draining, feature disable or extra request. Nonmatching text remains UNKNOWN.

The source-qualified runtime-shell request (`RSC:1`, `Next-Router-Prefetch:3`, no segment subtype) has a narrower output claim. A marked partial response may postpone a lazy rendered child beneath a known React Suspense boundary with a fully fulfilled fallback. Required tree/Map/metadata/type/module references, other component props, plain or promise references, missing fallbacks and cyclic fallback output remain blocking. The same model reached through another required path is still required. This proves only the represented shell output, preserving partiality; it does not claim a complete route. Synthetic tests follow installed Next16.4 buffering and React partial-stream behavior. Real corpus validation remains pending.

The main navigation's declared `p` runtime-prefetch stream supports its source-produced `R`/Uint8Array or `r`/byte-stream framing. Exact byte lengths and explicit stream close are required. Its reassembled Flight has a separate required graph; nested errors and malformed data cannot disappear inside opaque outer bytes. A marked partial embedded prefetch may use the same qualified Suspense-output boundary rule, while the main navigation's references remain required. Decoded-byte, row and model-work budgets are shared across the outer and one permitted inner level. Other binary roles remain UNKNOWN. A complete marker never permits missing references.

A separate `embedded-partial-prefetch-representation` claim covers postponed lazy references in component props reached through the embedded `r` output graph. It requires the inner `~` marker and fulfilled root, tree, Map, component-type and eager metadata. Next stores this detached partial cache representation without rendering those props; the claim explicitly records `renderableOutputClaim: false`. It proves neither a renderable shell nor complete output for a later navigation. Missing plain or promise references, component types, required fallbacks, main-navigation data and complete-marker holes remain UNKNOWN. Nested framing and positive-error inspection still run over the whole bounded embedded stream.

The exact partial `data.r` edge can itself hold a canonical postponed lazy wrapper. `postponedCacheOutputs` is the mandatory count for the source-qualified cache-output role. `representedOutputs` may be zero only with a positive postponed cache-output count and a known typed tree. Existing direct-embedded and array counters retain their narrower descriptive subcategories; they do not grant permission independently. The serialized proof keeps `renderableOutputClaim: false`; main-navigation data, complete markers, plain/promise holes and errors remain blocking.

The cache-output role starts only at typed `r` in a source-qualified partial cache response. It follows fulfilled ordinary-model and own-path aliases, arrays, and known host/Fragment `children` edges. Component types, keys, fallbacks, other props, imports, promises, collections and eager metadata remain independently required. Existing embedded component-data rules remain narrower and separate. Embedded `p` retains its partial-representation stage. A source-qualified header3 response with its actual `~` marker uses the distinct `runtime-shell-cache-representation` stage; this stage can also represent a fulfilled module-element fallback with fully known props. Neither stage claims the legacy renderable shell. Historical held prototypes and captures retain their original unqualified verdicts.

Semantic reference visits retain the complete incoming permission context, including array-root versus array-item state. A shared model seen on a permitted edge is checked again on a required edge. Structural parent readiness does not discharge those semantic checks, and changing array order cannot change which required dependencies must be known.

On a known Suspense element with a fulfilled props object, an omitted `fallback` property is React's empty fallback, as are literal null and explicit undefined. `knownEmptyFallbacks` records those cases. An unresolved fallback reference remains UNKNOWN; resolving the props object never supplies a missing model row. An empty fallback also proves no visible application content, which remains subject to the ordinary readiness checks.

Within the partial embedded cache representation only, a fallback React-element tuple may name a fulfilled, structurally valid Flight `I` module record when all of its props and eager dependencies are fulfilled. `representedComponentFallbacks` records this representation, while `renderableOutputClaim` remains false: the observer never invokes that module or claims its rendered fallback is known. A bare module tuple, missing type or prop reference, complete-marker hole and protocol error still reject. The ordinary renderable RuntimeShell claim retains its stricter fallback rule.

Passive native-environment metadata separately records the actual executable/launch and collector-source hashes, the four public worker files under the app manifest's serving root, and bounded existing Puppeteer target-manager events for the actual isolated context. It adds no browser flags, discovery commands or application requests. Missing files/process/target facts and event overflow remain explicit. A read-only end snapshot records the controller and registrations and rechecks the same public files within the remaining original cleanup deadline. It neither awaits worker readiness nor mutates a registration. Unknown, changed, pending and timed-out facts remain explicit; the snapshot does not attest every intermediate controller state. This metadata makes no producer-certificate or native-control acceptance claim. The complete operator fingerprint map remains required independently of the two observed source-file hashes.

Canonical plain outlined references may project fulfilled own data, including a decoded React element's `props`, `type`, `key` or null `ref`. Raw tuple indices do not stand for those element properties. Paths preserve the incoming required role, use bounded alias/lazy traversal and share the existing model-work budget. Missing eager parents or properties, deleted undefined fields, inherited properties, unresolved lazy or promise traversal, imports/exports and unsupported typed path forms remain UNKNOWN. Global errors and explicit root action failures remain blocking even when their root result is reached through a path. Opaque text stays literal.

A finite self-reference can reuse an actual materialized same-model container only after the selected own-data target is located and all eager parents are validated. An unresolved reference string is never an anchor. Cross-record or alias-to-container cycles remain UNKNOWN because the installed decoder's behavior depends on initialization order; collecting the whole body does not make those cycles fulfilled. Required-role and global-error checks remain independent of the anchor.

Nested outlined projections retain their active parent traversal only within the same backing model. That reuse is provisional: the enclosing traversal must still validate every eager sibling before returning a known result. This avoids restarting a pending parent repeatedly without caching an unfinished proof. Cross-model contexts retain independent validation, and the existing depth64 and shared100000-work guards still reject unique deep or oversized graphs.

Completed parent readiness can be reused within one bounded body parse for the exact parent object, origin model and forced-element check. Only a standalone same-model projection publishes certificates, after its entire parent list succeeds; nested provisional checks never publish one. Reuse must fit the verified relative depth span within the same depth limit and still consumes a model-work step. These structural certificates do not replace the later required-role, component-type, fallback, protocol-error or action-failure checks.

Fully inspected reference-free JSON subtrees have a separate local readiness cache keyed by exact object and forced-element mode. A dollar-prefixed string, skipped element, conditional anchor, opaque/binary value or skipped own `__proto__` field disqualifies its enclosing candidate. Publication occurs only after all local fields succeed; it never certifies a reference-bearing ancestor. A cache hit still consumes the existing model step, must fit depth64, and contributes its full depth span to every active ancestor readiness check. Unique excessive work and cold or warmed depth65 still reject under the unchanged limits.

Core `protocolErrors` observations retain positively observed Flight errors and root action failures, including qualified embedded streams, even when HTTP completes without a CDP loading failure. Missing or nonzero observations reject both phases independently of the raw browser-failure partition. Known length-framed binary data is skipped correctly while scanning outer error records; arbitrary binary business data is not interpreted as nested Flight. Zero observed errors is not a claim that every optional unread body was semantically fulfilled.

Normal primary and companion capture require `--app-manifest <required-server-files.json>`. Before collector or browser IO, the actual file must match `runtime.build`, its SHA256 and its explicit `experimental.cachedNavigations` boolean. Each plan must contain this metadata:

```js
runtime.browserControl = {
  policy: controlCancellationPolicy, // exact exported policy object
  browserRevision: chromiumSWRRevision, // exact exported source revision
  compiledCachedNavigations: /* actual compiled boolean */,
  compiledManifestSha256: /* actual file SHA256 */,
};
```

Browser startup verifies the actual revision through `Browser.getVersion`. Reports retain the verified binding. Both finalizers and independent budget derivation validate the receipt again; optional extra-header event absence does not become invented header knowledge or a control exemption.

Prospective native-cache metadata retains Next-Url, Accept-Encoding, Cookie and Authorization hash dimensions and bounded, allowlisted response Vary knowledge. Actual browser cookie snapshots are normalized and hashed in RAM before application IO and before context close, ignoring expiry renewal fields. End reads use the remaining existing finite-settlement deadline. Boundary equality and observed Set-Cookie counts are recorded separately; they do not establish an unchanged intermediate principal epoch or enable the native-cache category. Cookie values and raw headers are never retained.

Independent byte receipts remain available when protocol parsing is UNKNOWN: passive stream captured-byte SHA256 and exact byte coverage, bounded CDP readback availability, and naturally completed proxy decoded-body SHA256. Readback availability does not establish a natural terminal. These facts cannot replace supported protocol framing, required dependencies or unique correspondence, and introduce no larger retention limit.

At typed Vary-param iterable edges only, a parser-branded Flight `T` yield is a literal string. Its text is never resolved as a model reference or parsed as a nested protocol row. An ordinary object with a `textValue` property has no such provenance, and a numeric-looking text yield never becomes a stale-time number. The existing closed-stream, required-reference and global-error checks remain in force.

Segment and standalone head prefetch inspection has a separate typed contract. The full unmarked representation must have actual GET/RSC1/prefetch1/postponed2/status200 observations and a verified compiled deployment binding. The inspector derives the segment request-key hash from the root-anchored single spine using Next's child/slot encoder, or verifies the standalone head shape. It compares that hash with the observed request header and applies Next's response-deployment-header precedence over optional body `b`. A staged node's pending `Promise<void>` grants only that node a partial, nonrenderable cache representation; a fulfilled void promise requires its output dependencies. Shared aliases and own paths cannot transfer partial permission to complete siblings. Envelope metadata, full framing, required eager data and positive protocol-error checks remain strict. A complete typed-body result alone cannot exempt `NativeOther`; only the fully bound Native certificate above can use it. Historical captures are not requalified.

Primary measurement retains its existing request-map membership and failure counter. Companion retains its existing observed-after-start counter and supplies those same IDs to the classifier. All-phase observations support correspondence and application evidence; unrelated optional observations do not create a new all-teardown zero-error requirement. Required application UNKNOWNs and errors still block. Each returned visit checks these gates and actual measured native costs before more work is scheduled. Already-started workers still clean up and checkpoint, and the first sanitized failure remains primary.

Mixed capture additionally requires `--browser-control <metadata.json>` with `--app-manifest`, recording the metadata file SHA256. Its declared scope begins before the first application IO and ends at the existing finite-settlement boundary. The actual four browser contexts must belong to the registered native identities. Mixed registration requires independently read `--head-app-manifest` and `--head-browser-control`; ordinary budget derivation requires both `--release-app-manifest` and `--release-browser-control <qualified-head-metadata.json>`. The latter file is read once, validated against HEAD's actual manifest and retained by SHA256 in the release plan. ORIGINAL metadata is never rewritten or automatically qualified as HEAD metadata. Browser revision, cache mode and control policy must match across phases.

Optional `runtime.browserControl.nativePublicSources` authority has protocol `qualified-serving-worker-sources-v1`, the exact `compiledBuild` and `compiledManifestSha256`, and four ordered `{file,bytes,sha256,gitBlob}` records for `sw.js`, `lib/offline-queue-db.js`, `lib/sync-service.js`, and `lib/clock-command-dispatch.js`. The expected hashes come from independent source qualification; capture reads cannot create or amend that authority. When supplied, pre-IO checks compare actual serving bytes to it, and a release phase needs its own independently qualified authority. This binding alone enables no Native exemption.
