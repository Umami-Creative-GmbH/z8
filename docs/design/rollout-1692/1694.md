## Compatible interfaces for dependent tickets

```tsx
<DataTableToolbar
  search={searchDraft}
  onSearchChange={setSearchDraft}
  searchLabel={translatedSearchName}
  filterControls={<ExistingPeriodAndPersonControls />}
  actions={<ExistingGenerateOrExportControls />}
  bulkActions={<ExistingDomainBulkActions />}
/>

<DataTable columns={columns} data={records} getRowId={row => row.id}
  mobileLayout="scroll" pinLastColumn>
  {table => <DataTablePagination table={table} />}
</DataTable>
```

- All pre-existing props/defaults remain compatible. `searchLabel` is optional and falls back to the existing localized search placeholder. `filterControls` is a React-node slot for a real multi-select/person/period control; it supplies no schema, string conversion, debounce, query, validation or execution controller. Reset still resets only the existing configured filters/search; a custom control retains its caller-owned reset behavior. `searchDebounceMs` remains the legacy compatibility prop; this component does not start a second debounce timer.
- `DataTable`'s optional child receives its existing TanStack table instance for pagination/selection presentation. No duplicate table state, `onReady` effect or exposed global controller. Existing controlled/manual table callers keep their existing facade, callbacks and query owner. Do not add this footer where the consumer already renders its own pagination.
- Sorted leaf headers expose `aria-sort`; fetching exposes `aria-busy` while rows and drafts remain mounted. Neither causes a fetch or clears a selection. Error/partial/stale meaning remains domain supplied.
- `DataTablePagination` wraps, keeps named size and first/previous/next/last controls available on phones, and announces the existing row count. It retains `totalRows`, options, selected-count facade and page-size callbacks. Holiday's existing cross-page selection count remains in its bulk toolbar; its pagination facade still does not invent a loaded-page selection count.
- Ordinary phone records opt into existing `mobileLayout="stacked"`; their rendered localized headers label the same cells and their single mounted controls. Comparison reports can use `scroll` and `pinLastColumn`. Do not render duplicate phone mutation forms or hide secondary fields to make them fit.
- `/reports/projects` adopts F1 `PageHeader` **atomically with an exact path opt-in** in `appPageOwnsHeading`. The task h1 remains present for pending, no-employee, admitted and refused states; access/data readers stay behind their existing boundary. Other reports and descendants remain shell-owned. Tests explicitly retain Vehicles and Calendar headings. This pilot is not completion of #1736's full page brief.
