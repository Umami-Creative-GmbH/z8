## Implementation and coverage comparison

Every capability above remains at the same domain boundary. The picker now uses one divided record surface instead of separate clickable cards, with native buttons, wrapped names, a bounded scroll area and four safe-area insets. Checking, activating and redirecting have distinct status copy. Pending feedback names the selected organization even when its row is outside the scroll area. Choices remain visible and disabled until activation finishes; an immediate ref guard prevents repeated submissions before React renders. Failure restores keyboard focus to the selected row and enables all choices.

Session network/5xx/malformed-response errors now show an inline retry instead of navigating back into an initialization loop or presenting an outage as a sign-in failure. Actual 401/403 session refusals still go to sign-in. Strict Mode does not duplicate initialization; results after unmount cannot navigate or replace the saved preference. These changes have failing-before/passing-after behavior regressions. Successful activation, restoration precedence, callbacks, no-org handling and the shared SSO/MFA helper remain authoritative and unchanged.

The existing API supplies names and IDs, not organization logos; no fixture imagery or replacement tenant branding was added. No forms, workspace navigation, settings permissions, timekeeping logic, shared primitives or generated catalogs changed.

### Explicit remaining limits

- Live SSO provider completion, MFA enrollment/verification, store-app/system-browser return and failed-IdP network callbacks require configured non-production identity providers/devices. Their client handoff, safe callback, failed-return/no-loop and no-premature-persistence behavior are covered by the component and shared-helper/endpoint suites; live provider acceptance is not claimed.
- Physical iOS/Android notch/home-indicator insets and native browser zoom were not available. CSS applies all four inset variables; desktop browser checks use zero inset values. The 200% capture is viewport/device-scale emulation. Sidebar checks do not apply to this standalone route.
- Network/invalid-session-response retry, no-organization arrivals and automatic preference restoration are covered by rendered component tests. They were not all repeated as separate browser fixtures. Runtime covers real admitted/restricted roles, pending refusal, lost membership and actual successful switching.
- New keys `setup:init.title`, `setup:init.selectionHint`, `setup:init.checkFailed` and `setup:init.retry` have static English defaults and pass extraction checks. Remote Tolgee synchronization/pull and translated-catalog acceptance require configured non-production Tolgee access; no secrets were read and generated catalogs were not edited manually.
- A complete production build/static-generation run and the full PostgreSQL suite were not repeated for this client-only route change. Real dev-route compilation, full types, focused endpoint tests and the disposable migration verifier passed. The root spec's known complete-build and catalog verification limits remain open.

The owned Next process was stopped and the fixture cleanup command removed only its verified label-owned containers. Ignored local manifests contain synthetic fixture configuration only.
