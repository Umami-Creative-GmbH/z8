## Interfaces and adoption instructions

`components/ui/page-header.tsx` is a server-compatible presentation component. Supply a translated `title` and optional React-node `scope`, `description`, `actions`, normal div props and `className`. It renders one `h1`; scope precedes the task, actions wrap beside/below it. Consumers continue to own permissions, selection, period, form state and commands. Apply container width in the page: a report can remain wide, a form can use its existing reading width. No global width/token/font reset was necessary.

`appPageOwnsHeading(pathname)` in `lib/navigation/route-metadata.ts` is the explicit migration list: **exact** `/`, `/time-tracking`, `/reports`. Locale normalization is shared with existing route metadata. All other paths retain shell ownership. Add a route here in the same change that adds/adopts its page heading in successful, unavailable and failed arrival states; descendants do not inherit adoption. Do not remove all shell headings or add page titles mechanically.

`AppErrorState` retains its translation/digest/retry inputs and adds optional `recovery` (`entry`, `workspace`, `admin`), `headingLevel` and `actions`. The admitting shell chooses these; presentation never grants admission. Locale failures default to safe entry recovery. The app boundary chooses level 1 for adopted routes and level 2 where the shell still owns `h1`. F2/F3 can reuse existing `Alert` and `Empty` families and this error surface; domain-specific empty/no-match/all-clear/restricted/offline text and recovery remain with each owner. Never reinterpret those as one business state enum.

`ThemeToggle` accepts an optional element `trigger`, preserving existing callers/defaultOpen. The same provider handles the phone overflow and existing desktop/auth/onboarding controls. No theme modes or saved preferences were removed.
