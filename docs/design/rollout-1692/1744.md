## Design and test intent

The reader is a manager checking a selected location's current roster between
operational tasks. The visual direction is a restrained roster ledger: location,
admitted scope, then comparable employee records. Domain vocabulary: assignment,
current roster, live work, break in progress, captured event zone. Existing blue
navigation, neutral canvas/card/borders, muted supporting text, and working/break
state colors remain within the app system. The assignment-versus-position note is
specific to this presence view. No metric cards, decorative location map, or duplicate
phone record tree. Existing app typography and F1/F2 primitives govern composition.
DFII: impact 3 + fit 5 + feasibility 5 + performance 5 − consistency risk 3 = 15.

Preapproved seams: assembled public location roster and route states, canonical
presence PostgreSQL reader/clock commands, public heading ownership resolver.
Component tests do not prove live browser revocation or server admission.
