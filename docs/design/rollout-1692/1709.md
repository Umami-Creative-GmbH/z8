## Final coverage and verification

The inventory above is retained in full. Requests now lead with an always-visible
pending count, warnings and search/type controls. Fast lanes follow the ordinary
request workspace; covering sections remain explicit and linked. The inbox adopts
one exact page heading without adopting its parent or review descendants.

The detail panel uses only freshly loaded detail actions. Loading, refetch failure,
missing detail and mismatched item IDs cannot inherit list decision rights. Held
and material-change actions continue to come from the existing evidence owner;
server decisions reauthorize in the active organization. Stale evidence sections
are withheld while fresh detail is unavailable. The existing domain decision
rights, transaction gates and source adapters are unchanged.

F3's carried gap is corrected for classified time corrections: the already
authorized exact request supplies its actual stored reason. It is displayed as
entered, including line breaks. Ordinary/manual/policy submissions and ambiguous
ordinary evidence remain redacted; existing sanitization suites caught and
prevented broader reason exposure. No extra evidence read, invented reason,
canonical authority fallback or time formula was introduced.

Bulk and detail rejection use one local TanStack reason-form presentation. Their
existing state owners retain reason lifetime, trimmed payloads, requiredness,
cancel behavior and failure recovery. Native submit and pending dismissal are
guarded. Search drafts and usable rows survive failed refresh with an explicit
warning; filtered-empty copy differs from an all-clear queue.

## Reproduction and quality

All work used this isolated checkout and a unique label-owned disposable fixture,
never Phase, normal env files, customer data or provider credentials. The private
helper copy awaits log-stream open before spawning Next. Real Better Auth login
used the public development captcha token. Private manifests/cookies remain
excluded from Git. Only owned fixture resources may be cleaned.

Run the guarded handoff's prepare/dev/auth steps, then use
`pnpm node docs/design/rollout-1692/1709/submit-requests.mjs <fixture>` for the four
initial real requests. Capture baseline/current compositions with `runtime.mjs`.
`actions.mjs` exercises decisions; its `bulk` argument resumes only the two-item
bulk phase after single decisions. That accepted run followed the earlier actual
single-decision run; the JSON does not pretend they were one uninterrupted run.
Use `submit-requests.mjs <fixture> boundaries`, `boundaries.mjs`, then
`submit-requests.mjs <fixture> captured`, `material.mjs`, `ui.mjs`, `readback.mjs`.
The scripts deliberately assert expected fixture state and do not reset requests.
