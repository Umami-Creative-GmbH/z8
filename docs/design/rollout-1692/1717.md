## Implementation and final coverage

Every inventory row above remains covered by the existing control/owner or the
explicit replacement described there. No field, command, destination, shortcut,
query parameter or permission was removed. No new domain calculation, schema,
form implementation, export or pagination owner was introduced.

- F1: `EquipmentOverviewHeader` consumes `PageHeader`; the exact `/equipment`
  opt-in removes the duplicate shell h1. Loading, setup and failed arrival retain
  the page heading. Detail, employee-equipment and settings routes retain their
  independent adoption/guards. The only shared metadata edits are the exact
  opt-in and its regression; no shared primitive was modified by this ticket.
- Scope precedes the task. The authorized read's organization-local `today` and
  explicit timezone appear with the scope; the real shell supplies organization
  identity and switching. Filters never change the meaning of the summary totals.
- One divided summary surface replaces four independent KPI cards. Native,
  keyboard-operable buttons retain all four filter/tab actions, counts and
  captions. On ordinary 390px phones it uses two columns; enlarged text can stack.
  Existing semantic colors, tokens, locale number/date formatting, font and theme
  remain authoritative. Calm operational clarity is the design direction.
- F2: the existing search (including name/type/max length), holder/type/former
  controls and clear action occupy `DataTableToolbar.filterControls`. No new
  debounce, table controller, query, sorting or pagination is added. The existing
  stacked Table continues to expose every field and the single row-action menu.
- F3: existing ActionPanels, native TanStack forms, confirmations, validation,
  typed payloads, request identity and mutation owners remain unchanged. Failed
  arrival now exposes a visible `Reload equipment` that calls the existing RSC
  refresh, rather than only telling the person to reload the page.
